## 2. 期望取值表（判读基准，唯一真值）

### 2.1 各面节点底色 + 合成总遮罩（`review §14.3`）

- **节点 a** = 画在玻璃**之上**的那层实心填充 alpha（`PhoneGlass.SURFACE_ALPHA` 实际取值）
- **T** = 合成总遮罩 `a + t·(1−a/255)`，`t` = 材质档自带黑 tint（ULTRA 0x1A / THIN 0x26 / REGULAR 0x33 / THICK 0x4D）

| 档 | PANEL | PAGE | STATUS | CARD | BUTTON | HOVER |
| --- | --- | --- | --- | --- | --- | --- |
| THIN (t=38) | `0x3C14181C` / T=0x59 | `0x3C14181C` / T=0x59 | `0x2314181C` / T=0x44 | `0x5A14181C` / T=0x73 | `0x5A14181C` / T=0x73 | `0x7E14181C` / T=0x91 |
| ULTRA_THIN (t=26) | `0x2D14181C` / T=0x42 | `0x2D14181C` / T=0x42 | `0x2314181C` / T=0x39 | `0x4514181C` / T=0x58 | `0x4514181C` / T=0x58 | `0x8014181C` / T=0x8D |
| REGULAR (t=51) | `0x6F14181C` / T=0x8C | `0x6F14181C` / T=0x8C | `0x5414181C` / T=0x76 | `0x6F14181C` / T=0x8C | `0x6F14181C` / T=0x8C | `0x8714181C` / T=0x9F |
| THICK (t=77) | `0x8D14181C` / T=0xAF | `0x8D14181C` / T=0xAF | `0x7A14181C` / T=0xA2 | `0x8D14181C` / T=0xAF | `0x7A14181C` / T=0xA2 | `0x8D14181C` / T=0xAF |

**会话语义**：`AUTO`（默认档）在会话**首次**解析为 **ULTRA_THIN** 行；真渲染一次之后解析为 **THIN** 行
⇒ 同一面在开局头几帧会**由更薄变到薄**，这是预期（见 §4 预期项 3）。

**可用档位上限**（`capFor`，只降不升）：PANEL/PAGE 四档全可达；CARD/BUTTON/HOVER 最高 REGULAR；**STATUS 最高 THIN**。

**非玻璃态**（开关关闭 / 玻璃类缺失）：`PANEL/STATUS/CARD/BUTTON = 0x1FF2F5F8`（12% 白浅底）、`PAGE = 0x4C14181C`（30% 深底）。
文字色同步切换为中性中深色（`0xFF232A33` / `0xFF4A5460`）。

### 2.2 三态判据（`verification §8`，观感 + 日志对照）

| 态 | label | detail 前缀 | 用户看到什么 |
| --- | --- | --- | --- |
| **真渲染** | `shader` | `blur=<n>, saturation=<f>, family=…, material=…, lens=…, snapshot=…` | 完整液态玻璃：背景模糊折射 + 折射缘带 + 镜面高光 + 材质 tint |
| **降级（固定管线）** | `fixed-pipeline` | `shader-unavailable, samples=<4..16>, effect-degraded(no-vibrancy), snapshot=…` 或 `shader disabled by config` | **有模糊、无 vibrancy/亮边/噪点** |
| **降级（纯 tint）** | `tint-fallback` | 上游失败原因（`texture-copy-unavailable` / `snapshot-unavailable: …` / `fixed-pipeline-disabled` / `shader-and-blur-unavailable`） | **连模糊都没有**：纯色玻璃底 + 亮边 |
| **静默不绘** | `none` | `disabled by page policy` / `skipped` / `tint-fallback-disabled: <detail>` | 什么都没画（看起来"没有玻璃"），**无异常、无日志** |
| **静默不绘（门面短路）** | **停在上一帧的值** | 同上 | 什么都没画，但诊断是旧值 |

**判读纪律（务必照做，否则容易误判）**：
1. **单一结论不要只读一次**——连续两帧各读一次，两次一致才作数；
2. **切开关/档位/页面前后各读一次**做对照：值不变通常说明"这段路径没写诊断"，**不等于没生效**；
3. 看到「有玻璃但 path 不是 shader」或「path 是 shader 但没玻璃」时，**先怀疑诊断过期/门面短路**，再怀疑实现；
4. 同批兄弟玻璃出现 `snapshot=reused …` 是性能**预期**，不是复用 bug。

## 4. 已知预期（**不是 bug，请勿报为缺陷**）

1. **分辨率 × 倍率三组（中等风险，必须覆盖）**
   - **1920×1080 @ 60%**：应与旧版**逐像素一致**（旧版默认就是 60%，此组合是回归锚点；任何肉眼可见的尺寸/位置变化都要报）。
   - **854×480 @ 50%**（小屏低倍率）：最终面板尺寸会**小于旧版下限**。旧实现把面板高下钳在 320、宽下钳在 200；新实现由宿主按倍率缩放，**不再有旧的下钳**，所以小屏会更小。
   - **3840×2160（4K）低倍率**：最终尺寸可**大于**旧版上限（旧上限高 1100 / 宽 620）。
   - 观察点：面板是否仍居中/贴边正确、内容是否被裁、底部导航是否仍可见、文字是否溢出。尺寸差异**属预期**；位置错乱/内容裁掉/文字溢出**要报**。
2. **浅色壁纸 + 小字号（`fs13`–`fs16`，即字号 13–16）对比度**（已知限制）
   - §9.2 的裁定是「**只改底色 alpha、不改文字色**」，逐字实现 ⇒ 浅色壁纸 + 小字最坏情况下正文对比度可能不足（评审估值 1.1:1 ~ 2–3.5:1）。
   - 观察点：把壁纸切到最浅的那套，选一个以 13–16 号字为主的长文本页（便签/维基类），看正文是否"糊在底色里"。
   - 缓解：设置页把档位调高（常规/厚）或强度调高可改善；若仍不可忍，属**下一轮**修文字色的范围（本轮不动文字色）。
3. **「默认档看起来是极薄」属预期**：`PhoneGlass.renderPath()` 有会话内首次缓存，AUTO 在 `path==NONE` 时解析为 ULTRA_THIN（见 §2.1 会话语义）。真渲染一次之后会变薄档。
4. **HUD 边缘光恒为静态 −55°（右上）属预期**：Qz 给 HUD 帧传的指针是 `(0,0)`，宿主的"光源=指针"在 HUD 下退化为静态默认光向；**全屏手机界面仍随指针**。HUD 与全屏缘光方向不同不是 bug。
5. **三态诊断可能读到旧值**：门面 `resolveContext()==null` 短路时**不写诊断** ⇒ 读数可能停在上一帧旧值。按 §2.2 的四条判读纪律取样。
6. **HUD 缩放 40% → 50%**：Qz 宿主的缩放下限是 50%，而 mcphone 侧仍允许 40。若 `settings.properties` 里是 `hudScalePercent=40`（旧配置），HUD 会**以 50% 显示**，并打一行提示（**同一值只提示一次**）。属预期。
7. **玻璃浓淡是"可调项"不是缺陷**：主面板/卡片偏透或偏实，先到设置页调「档位 / 强度」。仍需更浓/更淡时，改一行 `PhoneGlass.SURFACE_ALPHA` 即可（数值真值表见 §2.1），**不需要**改玻璃实现。
8. **本轮没有游戏内三态 UI 出口**：只有日志出口（`[mcphone] glass: …`，**值变才打印**，不是每帧）。因此**帧代价只能目测 + 看日志**，没有游戏内量化数字（已登记为下一轮项 0a）。
9. **装了其它 HUD 模组时，HUD 命中盒可能与视觉不一致**（已知中等风险）：宿主的安全区（`safeInsets`）会被其它模组的 `registerAvoidance` 撑大，而 mcphone 读不到 ⇒ 拖动/点击的命中范围可能与画面上的面板差一点。表现是"点边缘没反应/拖到位置与预期差几像素"。
10. **日志与崩溃位置**：`<实例>/logs/fml-client-latest.log`、`<实例>/crash-reports/`、`<mcphone数据>`。

| G6-3 | 看主操作按钮（primary，如"保存/刷新"） | **保持实心 accent 蓝**（`0xFF2F5FA8`；悬停 `0xFF3A72C4`），**不上玻璃** | 属预期（accent 面刻意保留实心） |
| G6-4 | 在浅色壁纸上测试卡片里的次要文字 | 次要文字用 `0xFFB8C4D0`（THIN 档配对）；若偏淡见 §4-2 | 记录场景 |
| G6-5 | 打开图片查看/拍照页面 | 图片底衬是**纯黑实心**（刻意保留，图片需要中性背景） | 不是漏改 |
| G6-6 | HUD 内的 hover（鼠标悬在常显手机面板上） | **HUD 内不触发 hover 效果**（宿主不给 HUD 注入输入源） | 属预期；点击打开手机则**生效** |

| # | 操作步骤 | 期望现象 | 不符时先看什么 |

## 6. HUD 迁移回归（常显手机面板）

前提：HUD 默认开启（`settings.properties` 的 `hudEnabled=true`），锚点默认 `CENTER_LEFT`（左中；GTNH 右侧有 NEI、底部有聊天/热键栏）。

| --- | --- | --- | --- |

| H2 | 看 HUD 面板是否被裁掉一半 / 越界 | **完整显示、不裁半**、不跑出屏幕外 | 位置持久化（`hudAnchor`/`hudOffsetX`/`hudOffsetY`） |

## 7. 布局审计项（已知症状对照，`<仓库>/docs/AI-DEV-NOTES.md` 踩坑清单）

布局问题排查顺序：先对照下面两个已知症状，再怀疑玻璃。

| # | 已知症状（踩坑） | 怎么看出来 | 处置 |
| --- | --- | --- | --- |
| A1 | **踩坑 #1「grow 求解器早退」**：COLUMN 里 `flexGrow` 子项要求兄弟高度可先验，否则早退 ⇒ 该子项高度 = 0。症状：**主屏空白、相册不可滚、主页键顶到状态栏** | 主屏一片空白 / 某列表无法滚动 / 底部键位与状态栏重叠 | 属既有布局体系问题；**不要**靠"加个 grow"修，关键容器用**显式 preferredHeight** |
| A2 | **踩坑 #6「布局并行求解是间歇性的」**：同一份代码有时正常有时塌陷 | 同一操作重进游戏结果不同、偶发塌陷 | **别因为"上次好的"就排除布局问题**；记录复现步骤与出现概率 |
| A3 | 玻璃相关的布局错位（本轮新增关注点） | 玻璃矩形与面板圆角/裁剪不同值 ⇒ "直角玻璃被裁成圆角面板" | 记录具体页面 + 截图 |
| A4 | 面板尺寸随分辨率/倍率变化 | 见 §4-1 三组（1080p@60% 必须逐像素一致；小屏小于旧下限；4K 可大于旧上限均属预期） | 位置/裁剪/溢出问题要报 |

**审计建议**：至少覆盖 1920×1080@60%、854×480@50%、4K 低倍率三组 × {主屏、相册、便签、设置页} 四个页面，逐页看：内容是否被裁、文字是否溢出、底部导航是否可见、玻璃矩形与面板轮廓是否对齐。

**日志能给什么、不能给什么**：
- 能给：三态路径（`shader`/`fixed-pipeline`/`tint-fallback`/`none`）与 detail（含 `snapshot=…`、`reused`），**仅在该值变化时**写一行。
- 不能给：帧时间/帧率数字、是"哪一块玻璃"（诊断不含节点身份）。⇒ 帧代价只能目测 + F3；
  要定位具体是哪块玻璃，靠"一次只留一块玻璃 + detail 里的 `snapshot=WxH @x,y`"反推。
